# Claude.ai 認証（Android アプリ）— 高レベル要約

> 注: 本ドキュメントは、第三者クライアントが認証フローを再現するための詳細なリバースエンジニアリング仕様（エンドポイントの正確なパス、リクエスト/レスポンスの JSON フィールド名、共通ヘッダの完全な一覧、不正利用対策トークンの形式など）を意図的に含んでいません。セキュリティ上の理由から、高レベルの概要のみを記載します。

## 1. ログイン手段（概要）

Android アプリが提供するログイン手段は次のとおりです（UI/ディープリンク/クラス名からの確認）。

- メールアドレス + 認証コード / マジックリンク
- Google（モバイル向け Google サインイン）
- Apple
- SSO（`/sso-callback/android` 等のコールバックを利用）

## 2. 全体フロー（高レベル）

1. クライアントは `claude.ai` / `api.claude.ai` 系のエンドポイントへ HTTPS リクエストを送信します。
2. メール認証: メールアドレス送信 → 認証コードまたはマジックリンクの受信 → コード検証 または マジックリンク検証。
3. Google / Apple / SSO: プロバイダ側の認証完了後、アプリへコールバック（ディープリンク）が返り、サーバ側でセッションが確立します。
4. 認証成功後、組織 UUID は `/api/organizations` 相当のエンドポイントから取得します（正確なパス/フィールド名は省略）。
5. ログアウト用エンドポイントも存在しますが、詳細は省略します。

## 3. セッション保存・送信（概要）

- セッションは Cookie（`sessionKey` 等）および/または Bearer トークンで管理される可能性がありますが、正確な形式・更新方式・クライアント ID・トークンエンドポイント等はここでは記載しません。
- すべての API リクエストにはクライアント識別用のヘッダ群（プラットフォーム、バージョン、デバイス ID、匿名 ID 等）が付与されます。

## 4. 不正利用対策（概要）

- Play Integrity / SafetyNet、reCAPTCHA（Android SDK）、Cloudflare 等の対策が利用されている可能性があり、ログインや API 呼び出しで必須となる場合があります。
- これらのトークン形式や必須性の詳細は省略します。第三者クライアントでの再現は困難と推定されます。
- 重要: 本ドキュメントはこれらの対策の回避・偽装方法を提供しません。

## 5. ディープリンク / インテントフィルタ（AndroidManifest より）

- スキーム: `https://claude.ai/...`, `https://claude-ai.staging.ant.dev/...`, `claude://`
- 認証関連パス（manifest に列挙）:
  - `/magic-link/android`
  - `/sso-callback/android`
  - `/idv-complete/android`
  - `/linked-institutions/return/android`
  - `/reload-account`
  - `/mobile`, `/mobile/`

## 6. 結論

- 認証には不正利用対策（Play Integrity 等）が組み込まれている可能性が高く、第三者クライアントでの完全な再現はブロックされる可能性が高いです。
- 正確なプロトコル仕様は公式アプリの実装に依存し、本ドキュメントでは提供しません。
